할 일 관리 CLI를 하나 만들어 줘. 지금 이 디렉터리는 비어 있으니까 Go 프로젝트 세팅부터
직접 해야 해. 모듈 이름은 `example.com/tasks`로 하고, 빌드하면 `tasks` 실행 파일이 나오면 돼.

쓰고 싶은 방식은 이래.

```
tasks add "우유 사기" --due 2026-09-01 --tag home --tag errand
tasks list
tasks list --status all --tag home
tasks list --json
tasks done 1
tasks rm 2
```

세부적으로 부탁할 것들:

- 할 일은 JSON 파일에 저장해 줘. 기본 경로는 현재 디렉터리의 `tasks.json`이고, `--file`로
  다른 경로를 줄 수 있으면 좋겠어. 파일이 아직 없으면 알아서 만들어 줘.
- `id`는 1부터 시작해서 하나씩 올라가고, 한 번 쓴 번호는 지운 뒤에도 다시 쓰지 마.
  삭제하고 새로 추가했는데 번호가 겹치면 곤란해.
- `add`는 제목이 필수고, `--due`(YYYY-MM-DD)랑 `--tag`는 선택이야. `--tag`는 여러 번 줄 수
  있게 해 줘. 날짜 형식이 이상하면 그냥 넘어가지 말고 오류로 알려 줘.
- 위 예시처럼 **옵션을 제목 뒤에 써도** 동작해야 해. `tasks add "우유 사기" --tag home`이
  안 먹히면 손에 안 익어서 못 쓸 것 같아. `--file`도 마찬가지로 하위 명령 뒤에 올 수 있어야 해.
- `list`는 기본적으로 안 끝난 것만 보여 줘. `--status open|done|all`로 고를 수 있고,
  `--tag`를 주면 그 태그가 붙은 것만 나오면 돼. 보여줄 게 하나도 없으면 빈 화면 말고
  사람이 읽을 수 있는 안내 문구를 내 줘. 이건 오류가 아니니까 종료 코드는 0이어야 해.
- `list --json`은 다른 스크립트에서 받아 쓸 거라 JSON 배열 한 덩어리로만 나와야 해.
  각 항목에 `id`(숫자), `title`, `status`(`open` 또는 `done`), `tags`(배열), `due`(문자열,
  없으면 빈 문자열)가 들어 있으면 충분해. 사람이 보라고 덧붙이는 문구는 섞지 말아 줘.
- `done`이랑 `rm`은 id를 받아. 없는 id를 주면 조용히 성공하지 말고 뭐가 잘못됐는지
  stderr로 알려 주고 종료 코드도 0이 아니게 해 줘. 아예 모르는 하위 명령도 마찬가지야.
- 각 명령이랑 오류 케이스까지 테스트가 있으면 좋겠어. `go test ./...`가 통과하는 상태로 만들어 줘.
- README에 설치랑 위 명령들 사용 예시를 적어 줘.

외부 라이브러리는 안 썼으면 해. 표준 라이브러리로 충분할 것 같아.

작업은 중간에 나한테 물어보지 말고 끝까지 알아서 진행해 줘. 계획만 세워 놓거나 "이렇게
하면 됩니다" 정도로 멈추지 말고, 실제로 코드까지 다 만들고 테스트가 통과하는 상태로
만들어 줘. 위에 적은 것들이 전부 해결됐다고 스스로 확인이 될 때까지 계속 진행하고,
다 끝나면 뭘 어떻게 했는지 짧게 정리해서 알려 줘.
