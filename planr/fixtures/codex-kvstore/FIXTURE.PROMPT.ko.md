셸 스크립트에서 부려 쓸 작은 키-값 저장소가 필요합니다. 이 디렉터리는 비어 있으니 Go
프로젝트부터 직접 만드셔야 합니다. 모듈 이름은 `example.com/kv`로 하고, 빌드하면 `kv`
실행 파일이 나오면 됩니다.

명령은 이게 전부입니다.

```
kv set <key> <value>
kv get <key>
kv del <key>
kv list
kv compact
```

저장은 추가 전용(append-only) 로그 파일 하나에 합니다. 기본값은 현재 디렉터리의
`kv.log`이고 `--file`로 다른 경로를 지정할 수 있습니다. `set`과 `del`은 레코드를 덧붙일
뿐이고, 파일을 다시 쓰는 건 `compact`뿐입니다.

정말로 견뎌 줬으면 하는 것들입니다.

- **재시작.** 명령마다 별도 프로세스입니다. set한 값은 그대로 남아야 합니다.
- **쓰다 만 레코드.** 스크립트라 중간에 죽습니다. 로그 마지막 레코드가 잘렸거나 깨졌으면
  그 앞까지 전부 읽어 들이고 계속 동작하면 좋겠습니다. 중단된 그 쓰기 하나를 잃는 건
  괜찮지만 나머지를 잃는 건 곤란합니다.
- **동시에 쓰는 두 스크립트.** `kv set`을 스무 번 병렬로 돌리면 뒤에 키가 스무 개 있어야
  합니다. 열아홉 개도 안 되고 파일이 깨져도 안 됩니다.
- **`compact`.** 덮어쓰기가 쌓이면 로그가 커집니다. `compact`는 아직 살아 있는 값만 남겨
  다시 써야 하고, 도중에 죽으면 반쯤 쓰인 파일이 아니라 **원래 로그가 온전히** 남아야
  합니다.

나머지 동작입니다.

- 없는 키나 지운 키에 `get`을 하는 건 크래시가 아닙니다. stderr에 알리고 0이 아닌 코드로
  끝내 주세요. `if kv get x; then`이 동작해야 합니다.
- 없는 키에 `del`도 마찬가지로 0이 아닌 종료에 stderr 메시지입니다.
- `list`는 `키<TAB>값`을 키 순으로 한 줄씩 출력하고, 지운 키는 나오지 않습니다. 빈
  저장소는 아무것도 출력하지 않고 0으로 끝납니다.
- 키와 값은 한 줄짜리 평문입니다. 값에 공백은 들어갈 수 있고, 탭이나 개행이 든 값은
  이스케이프하는 대신 거부해도 됩니다.
- 하위 명령이 없거나, 모르는 것이거나, 인자 개수가 틀리면 조용히 넘어가지 말고 메시지와
  함께 오류로 끝내 주세요.
